# Discord 포럼 정산 기능 의도

사용자가 직접 만든 Discord 포럼 포스트 안에서 여러 사람이 각자 결제한 비용을 기록한다. 각 사용자는 같은 포스트에서 자신이 보낼 돈과 자신과 관련된 정산 내역을 확인할 수 있다. 포스트는 정산을 묶는 기준이다. 정산마다 데이터베이스에 개별 기록을 추가한다. 등록이 완료되면 현재 포스트에 공개 답장을 남기고, 조회 결과·오류 안내·계좌 정보는 명령을 실행한 사람에게만 보여준다.

## 포럼 정산

| 명령 | 동작 |
| --- | --- |
| `/정산` | 현재 포스트에서 결제자가 참여자를 선택하고 총액을 입력한다. 저장 후 이번 기록의 총액과 참여자가 결제자에게 보낼 금액을 포스트에 공개 답장으로 보여준다. |
| `/정산확인` | 현재 포스트에서 내가 보낼 금액을 받는 사람별로 합산해 보여준다. 상대가 등록한 계좌가 있으면 해당 줄에 계좌 정보를 표시한다. |
| `/정산세부` | 현재 포스트에서 내가 보내는 쪽 또는 받는 쪽인 정산을 한 페이지에 한 건씩 보여준다. 이전·다음 버튼은 오프셋으로 이동하고 같은 비공개 답장을 갱신한다. |
| `/계좌등록` | 폼에서 국내 은행 하나를 선택하고 계좌번호와 예금주명을 입력한다. 주요 은행을 먼저 보여준다. 검증 후 등록 또는 교체한다. 입력 오류는 본인에게만 안내하고 재시도를 제공한다. |
| `/계좌삭제` | 자신의 계좌를 삭제한다. 이후 조회에서 그 사람의 송금액만 표시한다. |

- 봇이 설치된 서버의 모든 포럼 포스트에서 정산 명령을 사용할 수 있다. 포럼 포스트는 사용자가 직접 만든다.
- 같은 포스트에서 여러 사용자가 기록할 수 있고, 한 사용자가 여러 번 등록한 비용도 각각 별도 기록이다. 포럼 글 작성자와 개별 비용 결제자는 서로 다를 수 있다.
- 기록을 만든 사람은 `/정산세부`에서 자신의 기록에 표시되는 버튼으로 총액·참여자를 수정하거나 기록을 취소할 수 있다. 취소된 기록은 합계와 상세에서 빠진다.
- 실제 송금 실행, 송금 완료 표시, 미납 상태 추적은 이번 범위 밖이다. 송금 여부와 관계없이 취소되지 않은 기록을 계산에 포함한다.

## 금액과 조회 예시

결제자는 자신의 몫을 포함해 1/N로 나눈다. 결제자 자신에게 보내는 금액은 표시하지 않는다. `45350`, `45,350`, `45,350원`은 모두 45,350원이다.

예를 들어 B가 45,350원을 결제하고 A·C·D를 선택하면 4명으로 나눈다. 각자 11,337원을 기본으로 계산하고, 2원이 남으므로 결제자 B까지 포함한 4명 중 서로 다른 두 명을 무작위로 뽑아 1원씩 더한다. B의 등록 결과에는 A·C·D가 B에게 보낼 몫만 표시한다. 배정은 기록에 저장한다. 총액이나 참여자가 실제로 바뀔 때만 다시 뽑는다.

A가 같은 포스트에서 B에게 3,000원과 2,000원, C에게 4,000원을 보내야 한다면 `/정산확인`은 `A → B: 5,000원`, `A → C: 4,000원`을 보여준다. 서로 주고받을 금액은 상계하지 않는다. `/정산세부`에서는 `A → B`, `B → A`처럼 A가 당사자인 항목을 볼 수 있다. 기록에 A가 참여하더라도 `B → C`처럼 A와 무관한 항목은 가린다.

## 계좌와 답장

- 계좌는 Discord 사용자 ID에 하나씩 등록해 봇이 설치된 서버에서 공통으로 사용한다. 등록은 정산 명령과 분리한다. 은행별 하이픈과 입력 검증은 다모아 Backend의 계좌번호 처리 방식을 따른다.
- `/정산확인`에서는 송금액 옆에 최신 계좌의 `은행명 계좌번호 예금주명`을 코드 블록으로 보여준다. 계좌가 없으면 금액만 표시한다.
- 공개·비공개 답장은 생성 1분 뒤 워커가 삭제한다. 최신 결과는 현재 포스트에서 `/정산확인` 또는 `/정산세부`로 다시 열 수 있다. 같은 조회를 다시 열면 아직 삭제할 수 있는 이전 답장은 워커가 지운다.
- 계좌가 등록·변경·삭제되거나 정산 기록이 수정·취소되면, 영향을 받는 답장의 1분 예약을 없애고 워커가 즉시 삭제하도록 요청한다. 다음 조회는 최신 기록과 계좌를 읽는다. 만료된 Discord 응답 토큰으로는 삭제할 수 없다.

## 교체 범위

기존 `!ping`, 예약 GIF 발송, 웹 상태 페이지, OAuth 초대·콜백을 제거하고 이 정산 기능으로 교체한다. 구현 절차와 검증 기준은 [정산 기능 명세](../spec/정산기능-spec.md)에 정리한다.
